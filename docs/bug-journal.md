## 2026-11-25, Pacific time

- **15:38, source verification.** The default `Play-VIctory.cmd` and its `fast` selector use the same local release. Its SHA-256 matches the build from `pareto-rtx-fast` at `fabb872`. - **15:39, descriptor lifetime and idle pools.** Moved the bindless buffer sweep and its previous ranges onto their owning host heap. A list holds each stride buffer it uses. A deferred sweep verifies the stride buffer identity before reading a heap. The periodic budget check can now drain expired pieces and trim completely free blocks from the texture and upload pools. Busy allocators retry on their next opportunity.
- **15:41-15:42, initial comparison.** Both releases used fresh copies of the same opening save and warmed cache. The first comparison stopped each process when Windows commit headroom dipped below 2 GiB. Neither reached the 1,000 draws/frame threshold. The baseline reported 4,241 MiB of live texture staging, 277 MiB of commit headroom and 7,648 MiB of free physical memory in its pressure log. The first candidate reported 2,870 MiB of staging when it first signaled pressure, at a different frame. Those samples cannot quantify memory savings.
- **15:45, staging admission.** The pressure cap had applied before catch-up tripled the budget, and early prefetch could add its own allowance. On auto settings, the final shared budget now limits speculative staging to 16 MiB/frame under pressure or 32 MiB/frame on a limited-RAM host with at least 1 GiB of live staging. A single texture can cross the limit. Required material bakes keep their existing budget and explicit stage-budget overrides take precedence. The maintenance pass also releases all eligible spare staging blocks under host pressure. Release GPU suite: 329 passed, 34 ignored.
- **15:46-15:48, release comparison on the RTX 5090.** Repeated from the same copied save and the same initial cache with the normal Pareto rendering settings. ## 2026-11-28, branch `coolfox/ultimate3`

- **Scope.** `git log --oneline 1298b14..2f881b7`: eight commits. HLE fixes from the GDK headers, the shader half of a shadow-mask fix, a reverted typed-store attempt, an asset-policy exemption and an interpolation fix for mesh programs. The follow-up work on `work/agent-c` is listed at the end and has not been pushed.
- **`6d8ac40`, HLE returns from the GDK headers.** We wrote `XMEM_WORKING_SET_STATISTICS` as 0x50 bytes, but the console struct is 0x78 (`xmem.h`), so the title's buffer kept stale bytes in the six trailing fields. Those fields are now zero-filled, `GameUsedPeak` holds the current use, and offset asserts lock the layout. `AcpHalAllocate/ReleaseShapeContexts` return `ACP_E_ALREADY_ALLOCATED`/`ACP_E_NOT_ALLOCATED` (`acphal.h`) instead of `E_FAIL`. xg texture-computer slots 0x18/0x20 return the stored size and alignment (`gen9/xg_xs.h`). They used to return `E_NOTIMPL`, which a caller read as a size of about 2 EB.
- **`2000b30`, `02990c2`, shadow-mask traces.** The title's shadow-mask traces read a ray-tracing structure's address from a heap-indexed descriptor. `view_address` gave up on that, so about five trace programs did not translate and shadows rendered black. The new `dynamic_view_address` reads the address from a third region of the strides table. It is emitted only with `VICTORY_SHADOW_ADDR`, which is off by default. This is the shader half only. `docs/shadow-mask-fix.md` specifies the host half (grow the table to 4×`SLOT_STRIDES_COUNT` dwords and fill it in the descriptor sweep) and its GPU test. That half is pending and must be validated on the GPU with the game.
- **`a8f77e1`, docs.** `env-vars.md` indexes the roughly 60 `VICTORY_*` switches a user sets, out of about 575.
- **`6ce34d4`, reverted by `33893cf`, partial typed stores.** A typed buffer store of one to three channels was translated as a masked `bufferStore.f32`. The validator rejects that: DXIL forbids a partial write mask on a typed UAV store ("store on typed uav must write to all four components"). The original refusal stands. Expressing such a store needs a read-modify-write of all four components.
- **`5384552`, asset policy.** The hex-run check flagged `crates/victory-gpu/src/launch_code.rs`. That file is the DXIL of our own `launch.hlsl`, not title data. It is exempted with its reason, like `bcpack-tables.bin`, and listed in `docs/asset-policy.md`. xtask: 6 passed.
- **`2f881b7`, one interpolation mode per output row.** The DXIL validator refused two mesh programs (`0bd4d80ad23b106b`, `63083c777948927a`) because row 9 packs a constant uint3 with a linear float. `constant_mixed_rows` makes every interpolated element of such a row constant, as the title's own PSV0 does. On a corpus of 2,960 shaders captured in play, 564 of 565 mesh programs now validate (562 before). Vertex/pixel (1,287/1,287) and compute (1,108/1,108) are unchanged. Still open: `72da0ba1efaec1e0`, whose mesh outputs (34,816 bytes) exceed D3D12's 32 KiB. It is emitted on purpose.
- **`work/agent-c`, not pushed.** `ec02c80` exports `XApuGetUtilization` (`mf_x/xapu.h:380`). It reports 500 streams (`maxStreamCount`, `xapu.h:102`) minus the streams active on all connections. `31c79e3` keeps rejecting DirectStorage requests with `SwizzleMode`, `SourceIsPhysicalPages` or reserved option bits (`gen9/dstorage_xs.h:272-316`) as before, but the warning now names those fields and stops after the first four per field. `ce0146f` adds a GDK header → module table to `architecture.md`. `8eace3d` makes CI build the diagnostics profile. GameInput trigger rumble is not implemented. XInput cannot drive the trigger motors, and `Windows.Gaming.Input` is not available here: the `windows` crate is a diagnostics-only optional dependency of victory-hle, without `Gaming_Input`, and nothing maps an XInput slot to a `Gamepad`. victory-hle lib: 178 passed, 3 ignored (was 176); xtask: 6 passed.
